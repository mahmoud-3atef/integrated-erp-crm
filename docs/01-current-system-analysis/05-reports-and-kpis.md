# 05 — التقارير ولوحات المتابعة وطريقة حساب كل مؤشر

> المصدر: `ManagementDashboardService`, `ManagementDashboard.aspx(.cs)`, `ManagementDashboard.NewArrivals.cs`, `ManagementDashboardMobile`, `ManagementDashboardApi.ashx`, `DashboardQueryService`, `WorkforceMovementDashboardService`, `NewArrivalsDashboardService`, `FinanceReportService`, `ProjectStatementService`, `EmployeeInsightService`, `EmployeeComparisonService`, `EmployeeLifecycleService`, `UserNotificationService`.

## 0. قواعد مشتركة في كل التقارير
| القاعدة | التعريف في الكود |
|---|---|
| التوقيت | كل التواريخ `DATEADD(HOUR, 3, …)` (UTC ⇒ السعودية)؛ "النهارده" = `EmployeeInsightService.SaudiToday()` |
| بداية التقارير | `ReportStartDate = 2026-07-01` — أي فترة تبدأ قبلها بتتقص (`NormalizeReportStartDate`) في لوحة الإدارة والتقرير المالي |
| المشاريع الداخلية المستبعدة | في لوحة الإدارة/المالية بالكود: `pro00137` (InActive) و `HeadOffice`؛ في لوحة المديرين بالاسم: `InActive Employee`, `HeadOffice`, `Head Office (Care-Pro)` |
| عمالة قطاع الأعمال | `new_empidnumber LIKE 'BS%'` |
| تسكين معتمد | label الإنجليزي = `approved` (عمليًا `statuscode = 100000009`) ومش ملغي |
| فاتورة سارية | label مش فيه `cancel`/`ملغ` |
| قوة العمل الحالية | `statuscode IN (100000000, 100000001, 279640014, 279640013, 279640018)` = على رأس العمل + إجازة + إجازة عميل + موقوف + مريض |
| نهاية المباشرة | `new_enddate`، أو قبل المباشرة اللي بعدها، أو أول رجوع للسكن (نفس قاعدة التحضير) |
| المهمة المتأخرة | تاريخ الاستحقاق `scheduledend` عدّى، أو مفيش استحقاق ومفتوحة أكتر من 3 أيام (`NoDueDateLateDays = 3`) |

## 1. لوحة الإدارة التنفيذية (`ManagementDashboard.aspx` — Team `CareAdmin`)
نفس البيانات بتتعرض على الموبايل (`ManagementDashboardMobile.aspx` + PWA manifest) وتطبيق Flutter عن طريق `ManagementDashboardApi.ashx`.

### 1.1 بطاقات KPI (`GetKpis(from, to)`)
| المؤشر | طريقة الحساب |
|---|---|
| إجمالي المشاريع | `COUNT(new_project)` بدون المشاريع الداخلية |
| المشاريع النشطة | نفس السابق + `statuscode = 1` |
| إجمالي العمالة | `new_employee` رقمه `BS%` ومشروعه مش داخلي |
| العمالة النشطة | + `statuscode = 100000000` (على رأس العمل) |
| عمالة في السكن / CurrentHousingWorkers | + `statuscode IN (279640000, 279640001)` (مرتجع / في السكن) — **نفس الرقم مكرر في بطاقتين** |
| المباشرات في الفترة | عدد `new_empwork` اللي `new_startdate+3h` في الفترة، العامل `BS%`، المشروع مش داخلي |
| الرجوع للسكن في الفترة | عدد `mw_lodginorderdetails` المعتمدة غير الملغية اللي `mw_arrivedate+3h` في الفترة |
| عدد الفواتير | `new_invoice` غير ملغية، `new_todate+3h` في الفترة، المشروع مش داخلي |
| قيمة الفواتير | `SUM(ISNULL(new_netsalarywithvat, new_totalamount))` لنفس الفواتير |
| المحصل | `SUM(new_totalpaidamount)` لنفس الفواتير |
| المتبقي | `MAX(0, القيمة − المحصل)` |
| نسبة التحصيل | `المحصل / القيمة × 100` (منزلة واحدة) |
| مهام مفتوحة / متأخرة / منجزة | من `task` (SDK) — مفتوحة `statecode=0`، متأخرة حسب القاعدة، منجزة في الفترة `statecode=1` |

### 1.2 التنبيهات التنفيذية (`GetExecutiveAlerts`)
مستحقات تحت المتابعة (المتبقي > 0 ⇒ تحذير)، عمالة في السكن (>0 ⇒ معلومة)، حركة رجوع للسكن (الرجوع > المباشرات ⇒ خطر)، مهام متأخرة (>0 ⇒ خطر).

### 1.3 تبويب النظرة العامة
| التقرير | الحساب |
|---|---|
| اتجاه الفواتير `GetInvoiceTrend` | لكل شهر: عدد/قيمة/محصل الفواتير السارية (اختياري لمشروع) |
| اتجاه الحركة `GetMovementTrend` | لكل شهر: عدد المباشرات مقابل عدد الرجوع المعتمد |
| المباشرات حسب المشروع / حسب مدير المشروع | `GROUP BY new_projectid` / `project.OwnerIdName` في الفترة |
| آخر المباشرات / آخر الرجوع | أحدث السجلات في الفترة |
| الرجوع حسب المشروع / المدير / **السبب** | `GROUP BY` على `new_backreason` بالـ label الإنجليزي (القيم اليتيمة تظهر "غير محدد") |
| ذمم المشاريع `GetProjectsReceivable` | لكل مشروع: فواتير الفترة، القيمة، المحصل، المتبقي |

### 1.4 تبويب السكن
| التقرير | الحساب |
|---|---|
| أعمار السكن `GetHousingAging` | العمال حالتهم في السكن + آخر أمر تسكين **مفتوح** (`new_leavedate IS NULL` و `new_housingstatus = 1`)؛ الأيام = `DATEDIFF(DAY, arrive+3h, GETDATE())` |
| الشرائح | 0–3 أيام / 4–7 / 8–15 / أكتر من 15 |
| حسب السكن / حسب السبب | `GROUP BY mw_housingName` / سبب الرجيع |
| اتجاه دخول السكن `GetHousingEntryTrend` | لكل شهر وحسب نوع الدخول (حديث/مرتجع/عائد من إجازة) |
| متوسط الإشغال الشهري `GetHousingMonthlyAverageOccupancy` | CTE لكل يوم في الفترة: عدد العمال اللي عندهم إقامة سكن في اليوم ده (البداية = `mw_arrivedate`، النهاية = يوم بعد `new_leavedate`، ولو فاضي = النهارده)، ثم `AVG` لكل شهر. ملاحظة: مابيبصش على حالة الاعتماد، ولو `new_leavedate` مش متسجل العامل بيفضل "في السكن" حتى لو اشتغل |

### 1.5 تبويب "العمالة دخول جديد" (`NewArrivalsDashboardService`)
العمال اللي `new_dateofjoining` (تاريخ وصول المملكة) في الفترة؛ لكل عامل: أيام العمل وأيام السكن من تاريخ الالتحاق لحد النهارده (من المباشرات وأوامر التسكين).

### 1.6 التقرير المالي (`FinanceReportService`)
| التقرير | الحساب |
|---|---|
| أعمار الديون `GetAging` | العمر = من نهاية فترة الفاتورة (`new_todate+3h`) لحد النهارده للفواتير اللي متبقي عليها (`new_netsalarywithvat − new_totalpaidamount > 0.01`)؛ الشرائح ≤30 / ≤60 / ≤90 / ≤180 / >180 |
| أكبر المديونيات `GetTopDebtors` | أعلى المشاريع في المتبقي |
| التحصيل حسب مدير المشروع | القيمة والمحصل والنسبة لكل `OwnerIdName` |
| **تغطية الفوترة** `GetCoverage(year, month)` | لكل مشروع كان فيه مباشرات في الشهر (بنفس قاعدة نهاية المباشرة): عدد العمالة، المفوتر منهم (في `new_invoicdetail`)، وهل للمشروع فاتورة — **ده المؤشر الوحيد اللي بيكشف "إيراد مش متفوتر"** |

## 2. لوحة مديري المشاريع (`Dashboard.aspx` — `DashboardQueryService`)
- تحليل المديرين `GetManagersAnalysis`: لكل مدير مشروع: عدد المشاريع والعمالة الحالية (حسب `CurrentStatusCodes`) وتوزيعها (على رأس العمل / إجازة / موقوف-مريض).
- تحليل المشاريع لكل مدير، ملخص كل المشاريع، وقوائم العمالة مع البحث بأرقام الإقامة/الهوية (لصق مجموعة أرقام) وتصدير Excel.
- المدير الحالي بيتعرف من اسم المستخدم (`FindProjectManagerNameForUser` — مطابقة بالاسم).

## 3. حركة العمالة (`Operations_WorkforceMovement.aspx` — `WorkforceMovementDashboardService`)
| المؤشر | الحساب |
|---|---|
| عمال مباشرات جديدة / أوامر المباشرة | `COUNT(DISTINCT new_employeeid)` / `COUNT(*)` من `new_empwork` في الفترة |
| عمال رجعوا / أوامر الرجوع | `COUNT(DISTINCT mw_empid)` / `COUNT(*)` من التسكين في الفترة (**بدون شرط الاعتماد**) |
| العمالة في السكن حاليًا | `COUNT(DISTINCT mw_empid)` اللي `new_housingstatus = 1` (**بدون شرط `new_leavedate`**) |
| مشاريع في حركة | عدد المشاريع المميزة في المباشرات + الرجوع |
| المشاريع الأعلى حركة | لكل مشروع: المباشرات والرجوع |

## 4. المشروع
- **كشف حساب المشروع** (`Sales_ProjectStatement` / `ProjectStatementService`): رأس (العميل، الفترة، الإجماليات) + تفاصيل الفواتير والتحصيل في الفترة (+ أسعار السكن من تسكين السراير `new_thijridate`).
- **تفاصيل المشروع** (`Sales_ProjectDetails` / `SalesProjectDetailsService`): العمالة الحالية بحالاتها، الحركة، الفواتير وحالة تحصيلها (جزئي/كلي بالأرقام 279640003/279640004).
- **قائمة المشاريع** (`Sales_Projects` / `SalesProjectQueryService`): عدد العمالة الحالية لكل مشروع (`statuscode IN (100000000, 100000001, 279640014, 279640013, 279640018)`) والفواتير السارية.

## 5. ملف العامل 360 (`HR_EmployeeDetails`)
### 5.1 دورة الحياة (`EmployeeLifecycleService`)
أحداث: التسجيل، المباشرات، أوامر التسكين، الإجازات، الاستئذانات، الفواتير الشهرية؛ وخريطة أيام (آخر 24 شهر بحد أقصى) لكل يوم: شغل / سكن / إجازة / استئذان / لا شيء. يوم المغادرة مش محسوب، والنهارده بيتلوّن ومش بيتحسب.

### 5.2 التقييم (`EmployeeInsightService`) — متوسط موزون للمحاور اللي ليها بيانات
| المحور | الوزن | الحساب (الدرجة من 0 لـ 100) |
|---|---|---|
| نسبة التشغيل | 30 | أيام الشغل × 100 ÷ (أيام الشغل + أيام السكن) |
| رضا العملاء | 25 | 100 − 25 × (رفض العمل `backreason=1`) − 10 × (العميل رجّعه بدون سبب `279640000`) − 3 × (أخرى `4`) |
| الانضباط | 20 | 100 − 4 × أيام الغياب (من سطور الفواتير) − 2 × عدد الاستئذانات |
| الاستقرار | 15 | 70% × min(100، متوسط أيام المباشرة ÷ 180 × 100) + 30% × max(0، 100 − 20 × المباشرات الأقل من 30 يوم) |
| الربحية | 10 | (للـ CareAdmin بس) الربح = الإيراد (الفواتير) − المصروف للعامل − التكلفة الحكومية `new_govcost`؛ الدرجة = الربح ÷ الإيراد × 250 |
- تنبيهات: وثائق قربت تنتهي (الإقامة `new_expirydateg`، الجواز `new_expirydate`، العقد `new_contractenddate`) خلال 60 يوم (`AlertDays`)، وعامل في السكن أكتر من 15 يوم (`IdleHousingDays`).
- شارات وملخص نصي ذكي.

### 5.3 حسب المشروع والمقارنة (`EmployeeComparisonService`)
لكل مشروع: المباشرات، الرجوع وأسبابه، الفواتير. ومقارنة مع **الوسيط** (median) لزمايله في نفس المهنة/المشروع: نسبة الاستغلال، متوسط مدة المباشرة، معدل الغياب الشهري، مرات الرجوع في السنة، هامش الربح.

## 6. التنبيهات والمهام للمستخدم

## 7. تعارضات في تعريف المؤشرات (لازم تتوحد في النظام الجديد)

| المؤشر | التعريفات الموجودة | الرقم الحالي |
|---|---|---|
| عمالة في السكن | (أ) حالة العامل `IN (279640000, 279640001)` — لوحة الإدارة | **34** |
| | (ب) أوامر تسكين `new_housingstatus = 1` — حركة العمالة وأعمار السكن | **73** |
| | (ج) آخر حركة = تسكين معتمد ومفيش مباشرة بعده (المنطق الحقيقي للحركة) | **135** |
| أوامر الرجوع | لوحة الإدارة: معتمد فقط — حركة العمالة: كل الأوامر | |
| المشاريع الداخلية | بالكود (`pro00137`, `HeadOffice`) مقابل بالاسم (3 أسماء) | |
| الفاتورة الملغية | 4 صيغ مختلفة (راجع [03](03-option-sets-and-statuses.md#2-المطابقة-بنص-الـ-label-بدل-القيمة-label-text-matching)) | |
| قيمة الفاتورة | `new_netsalarywithvat` ولو فاضي `new_totalamount` — في أعمار الديون `new_netsalarywithvat` بس | |

⇒ في النظام الجديد كل المؤشرات دي لازم تتحسب من **سجل الفترات الموحد** (Period Ledger) ومن جداول الحالات بأكواد ثابتة، في **طبقة تقارير واحدة** (views/semantic layer) بدل SQL مكرر في كل صفحة.
